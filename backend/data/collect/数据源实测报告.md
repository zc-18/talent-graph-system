# 数据源实测报告（`采集合规说明.md` 附件证据）

本报告是 `采集合规说明.md` 的证据附件，逐条列出候选招聘数据源的 robots.txt 与入口实测结果。

- **原始数据**：`data/collect/probe_report.json`（39 个站点）、`data/collect/probe_ats_report.json`（接口级探测）、`data/collect/feishu_tenants.json`（飞书租户探测）。
- **探测脚本**：`data/collect/probe_sources.py`。对每个候选源只做两件事：① 取 `{origin}/robots.txt` 并解析 `User-agent: *` 分组下的 Disallow 规则；② 对候选入口发 **1 次** GET，记录 HTTP 状态、内容类型、最终 URL、是否重定向、页面中是否出现登录/验证码特征词。**探测阶段不采集任何数据**，站点间 sleep 1.5 秒。
- **探测时间**：2026-07-27。站点共 **39** 个：企业官方招聘官网 27 个、政府/公共就业平台 5 个、聚合平台 7 个。

## 读表须知（两个必须说明的口径问题）

1. **`robots 是否禁止目标路径` 一列是脚本的自动判定，只比对 URL 的「路径」部分，不含查询串。** 因此 BOSS直聘、猎聘这类"用查询串规则禁止检索"的站点，脚本判定为"否"，但**实际的职位检索必然携带查询串，会命中其 Disallow 规则**——本报告在「结论」列按真实语义给出"不采"，不以脚本的机械判定为准。这一点在答辩时会被追问，特此写明。
2. **部分站点的 `/robots.txt` 返回的其实不是规则文件。** 表中若 robots 字节数与入口页字节数完全相同（如 拉勾/牛客 11027、B站 4520、联想 5353、看准 3175、大疆 53914、科大讯飞 30939），说明该 host 对 `/robots.txt` 和入口 URL 返回了同一个页面（前端 SPA 外壳或 WAF 拦截页），即**该站点没有真正的 robots.txt**。这种情况我们按"无 robots 规则"处理，但**不因此就去采**——是否采集另按登录墙/反爬情况判断。
